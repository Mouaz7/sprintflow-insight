# 0021: Joint bootstrap delivery forecasts

Status: Accepted for B6. Date: 2026-11-18.

B6 exposes a single empirical Monte Carlo method. The existing C2 algorithm core remains available for later model comparison and evaluation; its unimplemented API/UI work is still tracked separately. B6 never silently selects Gamma-Poisson or EWMA instead of running the requested 10,000 bootstrap simulations.

Without usable history or any observed completions, the API reports zero simulations and an unknown positive-work target probability, rather than confusing missing evidence with impossibility. Zero-work targets and completion dates remain trivial facts. With usable history, each simulated future resamples complete historical periods with replacement. All answers use the same 10,000 paths through a fixed 1,825-day horizon. Capacity accrues uniformly within a sampled period, so a completion day is the ceiling of the remaining fraction of that period. This is an explicit modelling choice, not an estimate of actual daily scheduling. Calendar days include weekends. Keeping paths fixed makes completion dates independent of a change to the target-date question and keeps by-date quantities independent of a change to the remaining-work question. It also prevents confidence levels crossing because separate binary searches happened to draw different futures.

At confidence c, the delivery date is the empirical c-quantile of completion days. Unfinished paths sort after the horizon; they produce a null date when that confidence cannot be reached. They remain in the denominator. A by-date quantity is the largest x with at least c of the paths delivering x or more; consequently higher confidence means a lower, more cautious quantity. Target probability is the fraction delivering the requested quantity by the date. The API returns at most 20 integer-width histogram bins and an explicit censored-path count instead of shipping 10,000 samples. Counts use long arithmetic; no allocation depends on the range of quantities.

Throughput uses up to 104 complete observed ISO weeks in UTC, including zero weeks. The first partially observed week and current incomplete week are excluded. Only current visible tasks whose latest actual status is Done contribute their latest real completion; point/sprint snapshots do not move the completion date. Future imported transitions are excluded. Velocity replays retained task snapshots at completed-sprint closure, using up to 52 sprints and the lower median valid scheduled sprint length (14 days when unavailable). Later reopen/trash/deletion can change the retrospective scope. Different sprint lengths and missing retained history can reduce comparability.

An epic narrows unfinished work through its stories; historical capacity remains project-wide. The UI explicitly conditions epic dates on that capacity being allocated to the selected work. Taskless stories, zero-point unfinished tasks and missing history are reported. The active sprint's remaining recorded quantity supplies the default target; this is a quantity proxy, not a test of qualitative goal acceptance. Otherwise the default date is four periods ahead. Custom dates range from today to 1,825 days ahead; today allows zero additional calendar days. Past active-sprint deadlines allow no additional delivery, and deadlines beyond the horizon have no reported target probability.

The six-period warning is product guidance, not a validated minimum sample size. Resampling assumes exchangeable, independent periods and similar future capacity. It ignores seasonality, trends, dependency constraints, future team changes and uncertainty about unobserved delivery regimes. A constant history can give a degenerate simulation distribution; even 100% of paths is not a delivery guarantee. Calibration, alternative models and rolling-origin evaluation belong to C2/E1. The C2 reference bootstrap's binomial partial-period thinning differs from B6's uniform shared-path accrual; that difference must be evaluated and reconciled when C2 is wired.

The methodological context is [Forecasting: Principles and Practice, distributional forecasts](https://otexts.com/fpp3/toolbox.html#distributional-forecasts-and-prediction-intervals) and [bootstrapping time series](https://otexts.com/fpp3/advanced.html#bootstrapping-time-series). These explain simulated predictive distributions and why temporal dependence needs special treatment; they do not validate our independent raw-period model, six-period guidance or within-period assumption.

The endpoint performs project access checks before reads, permits archived-project readers and changes no stored work. A repeatable-read snapshot feeds a 256-entry bounded cache keyed by immutable inputs. The unsigned history seed is decimal text to avoid JavaScript integer precision loss. Equal history, parameters and UTC day give equal output. Query count is fixed; reading retained project history still scales with its row count. Automatic work above 10,000 units is rejected with a correctable message rather than silently truncated.

No schema change or chart dependency is needed. The lazy route reuses native SVG charts, tables, keyboard controls, Query and typed EN/SV text. The measured all-route gzip total grows from 251.59 to 261.92 kB; the budget moves explicitly 255→270 kB, with a separate 20 kB forecast chunk limit (9.11 kB measured). Entry 125 kB, CSS 15 kB and existing route budgets remain unchanged. URL parameters preserve applied queries; changing project resets them, and background refresh keeps an unapplied form draft.
