# ADR 0024: Task time, timers and sprint capacity

Status: Accepted

Time is independent from story points and PERT working-day estimates. V24 adds `task.estimate_minutes`, `time_entry` and `sprint_capacity`; B16 owns V22 and planning poker owns V23, so merge/deploy those migrations first. B4 is developed above the B7 branch to keep the new PR independently reviewable.

An estimate is optional: null means unestimated, zero is explicit. `PUT /projects/{projectId}/tasks/{taskId}/time-estimate` requires the parent task's revision. The existing PERT `/estimate` endpoint keeps its own semantics. Ordinary task writes cannot clear the time estimate. The response is a record carrying task id, estimate and the new revision.

A time entry is manual or timer-based. Task, project and person are fixed once created. One running timer per account is enforced by a PostgreSQL partial unique index, including concurrent starts across projects. Stopping rounds elapsed time up to whole minutes, with a minimum of 1 and maximum of 1440; fractions of a second are included. This cap is shown to users. If write access to an older timer's project has been lost (removal, Viewer downgrade, archive or trash), starting a new timer discards that unlogged timer. Completed entries remain intact. One day of timezone slack is allowed for a manually entered date relative to UTC; dates before 2000 are rejected.

ProjectAccessService checks every request. Project writers log their own time and capacity; Owner/Admin may manage another current writer. Viewers and archived projects may read. Writes take the project mutation lock; optimistic revisions protect estimates, existing entries, capacity updates and timer stops. A composite task/project foreign key prevents cross-project entries. Time changes and capacity changes emit the existing activity/realtime invalidation events without copying notes into summaries. The UI retains failed drafts and requires an explicit close/reopen after a revision conflict.

Sprint capacity counts Monday–Friday inclusively, then subtracts distinct weekday absences inside the sprint. Public holidays are entered explicitly. Availability scales minutes and optional point capacity; both are rounded down. Committed work includes Done tasks, unassigned work and work assigned to former members. Missing estimates and capacity are reported as warnings. Loads round upward so a fractional overload is not presented as 100%; arithmetic saturates safely at the integer display limit. The optimizer adapter supplies conservative whole-hour or point capacities with stable account-id keys, without implementing the C1 UI.

Reports use current live tasks and their current sprint assignment. Running timers are excluded until stopped; trash/moves may change scope retroactively. Variance compares only estimated tasks and separately reports all actual minutes and unestimated counts. Account deletion removes running timers, anonymizes completed entries and clears capacity. Anonymous hours remain in team/report totals. Task/project deletion cascades through time entries. CSV text cells use the existing quoting and formula-neutralization rules.

The frontend is lazy-loaded at `/time`, with project-scoped Query hooks, EN/SV copy, preserved editor drafts and a keyboard-scrollable report table. Time-entry lists use server-side keyset pagination; report rendering is bounded in batches. Report/capacity reads use bulk queries, independent of member count. The route measures approximately 15.10 kB gzip; all routes total 289.59 kB gzip. The aggregate ceiling is 295 kB with a dedicated 20 kB time-route ceiling; entry/tasks/CSS and coverage thresholds are unchanged. No dependency is added.
