# 0027 – Bounded imports, account portability and retained administrative audit

Status: Accepted. Implements B19 (#26).

CSV/Jira imports enter through `/data`: choose a file, inspect the read-only preview, map task/custom fields and workflow states, then explicitly confirm. Preview and commit reuse the same bounded pure parsers and mapping. Commit rechecks project access under the project lock, compares a SHA-256 fingerprint of the canonical request plus current definitions and membership, validates all rows, and saves at most 200 tasks atomically through the normal task application service. Neither project members nor stories are implicitly created. Owner/Admin may preserve historical milestones; ordinary Members import with current task timestamps. Viewers and archived projects cannot import.

A request has at most 1,000,000 characters, CSV has at most 64 columns and 8,192 characters per cell, and Jira JSON has depth/string/number limits, strict duplicate keys and a single document. Titles/descriptions retain the application's 255-character limit. Truncation is an explicit option; original source text is retained in provenance. Jira descriptions may be plain text or bounded ADF text. Scalars can be mapped to project-defined custom fields; decimals remain strings. Assignee email must resolve to current project membership. Identity objects from research exports are never turned into users.

V27 records the canonical request hash, receipt and per-task source keys/provenance. Repeating the same request returns its original receipt, including after a task is recycled or purged. A changed request skips existing `(project, format, source key)` entries; it never updates those tasks. A purged task loses its source key and can be recreated by a different request. Use external keys for overlapping batches. No source key means only exact-request replay protects against duplicates. A failed transaction writes no receipt, task, custom value, history, audit event or post-commit task event.

Historical import preserves created/started/completed **summary milestones**, not every original Jira transition, sprint, reopening or assignee history. The preview states this limitation. Source dates remain provenance even when history preservation is disabled. Preserve history only when its effect on metrics is intended; research evaluation must state this reduced fidelity. Full Jira project restoration is outside this contract.

## Account export

`POST /api/account/export` requires session authentication and CSRF. It has a separate two-per-account-per-minute rate budget. The client downloads a no-store ZIP containing explicit JSON projections, a versioned manifest and authorized stored attachment bytes. Queries use a repeatable-read snapshot and fetch bounded pages inside the transaction. Credentials, session/reset/unsubscribe tokens, server secrets and other participants' unrevealed poker votes are excluded. Attachment URLs are data; the server does not fetch them. Local file references are validated and opened without following a final symlink. Missing files abort the complete export rather than silently omitting them.

Scope is profile, preferences, personally attributed comments/retrospectives/time/capacity/notifications/votes/report metadata/audit, and collaborative content currently readable through membership in non-deleted projects. Archived projects remain readable. Workspace task content excludes recycled tasks. Legacy tasks and attachments have no creator/uploader identity, so authorship is not fabricated; they are included only via current project access. Former members retain their own attributed contributions, without gaining access to other former project content. Account deletion already removes/anonymizes the legacy email-owned contributions, preventing a later email registration from inheriting them.

At most two archive builders run concurrently per application instance; excess requests receive 429 without waiting. The default limit is 64 MiB uncompressed and 100,000 rows per section. A bounded in-memory ZIP is deliberate: clients receive either a complete successful archive or a clear 413/409. Operators can raise `SPRINTFLOW_ACCOUNT_EXPORT_MAX_BYTES` up to 128 MiB for an assisted export; larger accounts require an operator-run complete export. This is a concrete portability feature supporting Article 20 requests, not a certification that this subset or automatic response satisfies every controller's legal obligations.

## Administrative audit

The existing editable `activity_event` feed is not an audit trail. V27 adds an independent append-only audit with numeric actor/project references, captured role, fixed action/target and small trusted metadata. No uploaded content, free-form administrative text, email addresses, credentials or ZIP payloads are recorded. Successful project settings, membership/ownership, archive/trash/restore/purge, custom definition, WIP policy, activity moderation and other-author comment/retrospective moderation are recorded in the same transaction. Imports and account exports also record events. Failed operations leave no audit event.

Owner/Admin can read a project's retained audit with keyset pagination (1–100 rows). There is no mutation API. A database trigger rejects updates/deletes during the 90-day period; deletion of an account/project cannot cascade it away. A daily ShedLock job purges up to 10,000 expired rows. DB administrators can still alter the schema: this is application-level tamper resistance, not external notarization. Numeric identifiers are pseudonymous personal data subject to the documented 90-day retention. Purged project logs are retained for operators, not exposed by bypassing project access.

## Research subset and verification

The local `scripts/data/apache-subset.ts` converts an explicitly selected MongoDB JSON Lines export from the Apache collection of Montgomery et al.'s [Public Jira Dataset v7](https://zenodo.org/records/15719919), DOI `10.5281/zenodo.15719919` (2025-06-23). Data is CC BY 4.0; the dataset's scripts are MIT. The archive MD5 is `02f85309d966092ea130ca0797aea795`. See [the operator procedure](../import-export.md). The converter records provenance, hashes and project-specific bounded batches. Synthetic tests verify format compatibility and limits; they do not claim a complete 60 GB restoration or benchmark run.

Parser seeds replay in normal tests. `JAZZER_FUZZ=1` runs actual Jazzer coverage-guided exploration, separately bounded to 30 seconds per parser. A discovered arbitrary column name exposed an overly broad identity assertion; the invariant now matches the actual forbidden field prefixes and that input remains a checked-in regression seed. Role/archive/CSRF, atomicity/replay, exact decimals, append-only retention and scoped secret-free export use real PostgreSQL integration tests. MSW and browser tests cover preview invalidation, conflicts, keyboard confirmation, JSON ZIP download, Swedish mobile dark mode and axe.
