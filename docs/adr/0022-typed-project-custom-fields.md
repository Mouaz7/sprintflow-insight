# 0022: Typed project custom fields

Status: Accepted. Date: 2026-11-18.

B16 uses project-owned field definitions and separate typed task values. Definitions support text, exact decimal numbers, ISO calendar dates, a bounded option list and a current project member. A project has at most 20 fields; names are unique ignoring case. A field's type is immutable. An option still in use cannot be removed; deleting a field explicitly removes its values.

`task_custom_value` stores the matching text/number/date/member column, with checks enforcing exactly one type. Composite foreign keys tie each value to a task, definition and membership in the same project. User values reference the existing public membership id, not an email or global account id. Removing that membership clears the value through a foreign-key cascade; rejoining receives a new membership id and cannot regain an old assignment. Labels follow the current member email without saving another copy. Permanent task/project deletion cascades; task soft deletion preserves values for restoration.

Definitions are managed by Owner/Admin; task values are writable by Owner/Admin/Member. All readers, including Viewer and archived-project readers, may inspect definitions and values. Definitions use their own optimistic revision. Replacing a task's complete value snapshot requires its current task `If-Match`; changing values increments the parent task revision in the same transaction. A dedicated task drawer edits values after a task exists. Values stay outside the core task read model, so forecasts, metrics and ordinary task lists do not acquire per-task value queries.

Board filters, search filters, CSV and the future B15 automation conditions share one condition record and explicit null semantics. Missing values match only `IS_NOT_SET`, including for `NOT_EQUALS`. Text comparison is case-sensitive and `CONTAINS` treats percent/underscore literally; search's existing multilingual full-text matching is unchanged. Number/date fields support ordered comparisons; select/member fields use equality. A filter operand is limited to 200 characters to bound GET requests; stored text values may contain 2,000 characters. Decimal values use canonical strings in JSON to preserve up to 18 whole digits and 6 decimal places without JavaScript rounding. Calendar dates use years 0001–9999.

Project scoping precedes field lookup. SQL values are bound parameters; field/type/operator choices select server-owned predicates. Composite scope/range indexes support filtering and foreign-key cleanup. CSV reads definitions and values in bulk and applies the existing spreadsheet-formula escaping to headers and displayed values. No new runtime dependency is added. The B15 rule builder remains a separate phase; B16 supplies its typed condition contract and pure matcher.

Verification covers the V21 upgrade with unchanged task versions/history, composite scope/type constraints, membership removal/rejoin, every endpoint role in active and archived projects, atomic snapshots, concurrent writers, SQL/pure-condition agreement, precise decimals and CSV escaping. A 1,000-task export uses at most 20 prepared statements; matching uses at most 8. A local PostgreSQL plan for 1,000 numeric values used `custom_value_number` and returned the expected 10 rows in 0.44 ms; that fixture transaction was rolled back. EN/SV MSW tests, actual packaged-server Playwright flows, axe, responsive/help probes and image review cover the UI. Additional recovery checks exposed and corrected cached matches after field deletion and unbroken field-name clipping on mobile. Pure-core mutation testing killed 156/160 mutations (98%) with no uncovered mutations.

Measured frontend budgets: all route JavaScript is 277.28 kB gzip (B6: 261.92 kB). The aggregate ceiling becomes 285 kB for the definition route, task value drawer and shared filter/input code. Entry 117.50 kB, tasks 18.20 kB, CSS 12.50 kB and palette 4.71 kB remain within their existing limits. Definition and task value chunks each have a new 10 kB ceiling; task values load only when opened. No new package is added.
