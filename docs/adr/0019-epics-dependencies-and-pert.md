# 0019: Epics, dependency networks and PERT

Status: Accepted for B3. Date: 2026-11-17.

Epics group stories without changing sprint assignment. The roadmap combines explicit epic dates (falling back to linked sprint dates), completed story-point progress, sprint rows and aggregated arrows between epics. A story is complete only when it has tasks and every live task is Done. Deleting an epic detaches its stories and preserves their work.

The V17 foundation was delivered with B9 search and must not be replayed. V18 adds epic search; V19 belongs to realtime. B3 adds only V20, initializing existing estimate revisions to zero and marking them active without changing their values. Clearing an estimate retains an inactive revision marker; forecasts and reads ignore it. Re-creating the estimate advances that revision, so old drafts cannot resurrect a deletion or overwrite a replacement with a reused revision. Permanent task deletion removes the marker through the existing cascade. Hibernate validation and an upgrade test exercise this sequence on PostgreSQL.

Dependencies are directed blocker → waiting task. Composite foreign keys enforce project identity. A project row lock serializes writers; an iterative depth-first search rejects cycles and returns both task IDs and human keys. Trashed tasks retain edges for safe restoration; normal reads hide them. A 5,000-edge and 200-epic bound limits graph growth. Dependency blocks on the board are derived separately from manual blocks. Completed blockers satisfy their edges. Active-sprint work waiting on unfinished work outside the sprint receives a warning.

Pure scheduling code lives under workspace.roadmap.schedule. Deterministic topological forward/backward passes calculate longest expected duration and slack; ties prefer the path with greater variance, then the lower ID. An epic forecast includes its unfinished ancestor tasks from other epics or the backlog. Completed work is removed. Missing estimates contribute zero to the displayed partial duration, but suppress the promised finish and probability. Taskless stories also suppress those values. The UI displays both coverage and this limitation.

For independent task durations, PERT uses E=(optimistic+4×likely+pessimistic)/6 and variance=((pessimistic−optimistic)/6)². A normal approximation uses the sum of variances along the expected critical path. It does not model correlated delays or the maximum of near-equal random parallel paths, so deadline probabilities can be optimistic. They are planning indicators, not calibrated guarantees. The standard normal CDF uses the five-coefficient Abramowitz–Stegun 26.2.17 approximation (absolute error below 7.5×10⁻⁸); independent reference values and symmetry/tail cases test it. Monday–Friday working days count the start date inclusively; public holidays are not modelled. A past target has zero remaining-work probability.

Reference: [Malcolm et al., Application of a Technique for Research and Development Program Evaluation (1959)](https://pubsonline.informs.org/doi/10.1287/opre.7.5.646), [NIST normal distribution](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3661.htm), [NIST handbook information](https://www.nist.gov/mathematics-statistics/handbook-mathematical-functions-abramowitz-and-stegun).

Every read checks project membership; writes require Owner/Admin/Member and a live project. Epic edits/deletes, story assignment and existing estimate updates/deletes require If-Match. Clients capture the revision when opening/selecting the work, retain drafts on rejection and refresh project queries only after successful writes. Activity events also invalidate connected browsers through B1. React renders cycle keys and descriptions as text.

The lazy roadmap route uses native SVG and a complete HTML date/progress table. The scroll region supports keyboard scrolling. Native filtered task/story choices render at most 51 options even for a 5,000-item backlog. Viewer and archived-project screens remain readable and omit mutation actions. English and Swedish copy explains estimates, incomplete forecasts and cycle errors. No chart library or runtime message compiler is added.

Verification covers independent graph oracles, a 20,000-node chain, reference normal probabilities, real PostgreSQL migrations, concurrent opposite edges, role/archive/trash boundaries, version conflicts, bounded query count, MSW UI flows and the packaged application's browser flow. PIT includes the scheduling package. See the B3 completion evidence for measured results.

The all-route JavaScript budget grows explicitly from 220 to 240 kB gzip for B3 (measured 237.65 kB; roadmap 16.17 kB). Entry 125 kB, CSS 15 kB and existing route limits remain. The roadmap has its own 20 kB limit; it is loaded on navigation.
