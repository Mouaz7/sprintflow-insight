# ADR 0026: Verified mentions and opt-in email summaries

Status: Accepted

B8 uses V26 after the V22–V25 stack (#70–#73). Deploy those migrations in order before this change. Mentions are scoped to comments; task descriptions retain their existing behavior.

The server scans at most 20 distinct ASCII handles from each bounded comment. `@name` matches the local part of exactly one current member's email; `@name@example.com` is unambiguous. Addresses without a leading mention marker, closed backtick code spans, outsiders and ambiguous short names do not resolve. The client suggests existing project members and inserts full addresses using keyboard-accessible native buttons. It never chooses notification recipients. Project membership is checked again when the durable event is delivered. Self mentions produce no mention notification.

`comment_mention` stores the current resolved account ids. Its composite foreign key binds each comment to its project; comment/account deletion cascades. Adding or editing a comment updates the set and publishes only newly added recipients within the write transaction. Replays deduplicate using the existing source-event/recipient constraint. A remove/re-add is a new mention. Existing generic owner/assignee comment notifications keep their behavior. Realtime reuses metadata-only project invalidations; no mention roster or comment text is added to socket messages.

Email summaries are personal preferences, OFF by default. A read returns OFF/UTC without inserting a row. Daily delivery is at 08:00 local time; weekly delivery is Monday at 08:00, calculated with the selected IANA zone and calendar/DST rules. Changing settings requires the caller's revision; exposed revisions start at zero for defaults and one for saved rows. The existing account lock serializes first creation. Notification opt-out also pauses summaries. Without configured SMTP the scheduler skips account scans and preserves the delivery window.

[ShedLock](https://github.com/lukas-krecan/ShedLock) 7.11.0 uses PostgreSQL time for the distributed scheduler lock. Each sweep handles at most 20 accounts and each account is locked in its own transaction. Delivery rechecks the due time and preferences after taking the row lock, preventing simultaneous workers from sending the same window. The message contains up to 50 unread notifications created after the checkpoint and before the sweep cutoff, limited to projects the account can still read. Selection cutoffs and checkpoints are truncated to PostgreSQL microsecond precision so a rounded timestamp cannot fall between two windows. Mail failures retry after 15 minutes without advancing the checkpoint. Empty/paused windows advance without sending; successful mail records its actual send checkpoint. SMTP delivery is at-least-once across a process crash between acceptance by the mail server and committing the checkpoint; the lock is not a claim of transactional exactly-once email.

The opt-out link is an opaque, 90-day capability authenticated with the existing AES-256-GCM keyring and a dedicated associated-data context. It carries an account id, a subscription nonce and expiry. Re-enabling rotates the nonce so an old email cannot disable a new opt-in. Repeated valid opt-out is idempotent. Normal key rotation can honor previous keys; removing them invalidates old links, after which the profile remains available. GET `/email-preferences` only renders confirmation, including for mail scanners. POST `/api/digest/unsubscribe` requires the capability and standard CSRF protection but no sign-in, and returns no account details. It changes only email cadence, never in-app notification preferences.

The UI has EN/SV controls, retained failed drafts, explicit reload after a conflict and a public localized confirmation page. Email bodies are plain text; new mention summaries and known notification prefixes honor the account language. Credentials, tokens and message bodies are not written to delivery-failure logs. SMTP stays explicitly disabled in local browser verification; integration tests use a fake mail transport to exercise content, links, retries and window selection without sending real email.

The two ShedLock dependencies are backend-only. Frontend dependencies and bundle ceilings are unchanged. The full application measures 304.28 kB JavaScript gzip, Tasks 19.32 kB (20 kB cap), Profile 11.84 kB and the public opt-out route 0.75 kB with a dedicated 3 kB ceiling. Existing coverage thresholds remain unchanged.
